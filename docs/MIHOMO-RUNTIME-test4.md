# 辟尘 0.4.0-test.4：生效状态与应用放行

基线：`3a1e6f830ccb47147688c716e9c0da128631990a`，接续 `feature/mihomo-ui`，不更换原图标、不合并 main、不改动内核或 0.3.0-beta.1 模块。

## 改动

- Mihomo 创建 VPN 时真正应用既有 `bypassApps` 名单；应用放行绕过整个 VPN（代理和域名过滤），不是只免除广告。系统 hosts 不支持这种按应用豁免。未安装/当前不可见的应用单独提示，不假装已放行。
- 使用不可变的会话配置：显示本次实际应用的过滤开关、规则域名数、放行应用数；运行期间修改过滤、名单或规则，明确提示停止后重连。保存不等于已经生效；取消改动可消除对应提示。
- 代理总览与配置页加入实际生效卡片、应用放行入口；复用原应用列表、搜索和筛选。从代理进入名单不会意外开启旧 DNS VPN。
- 代理网络状态等候系统能力回调，再区分已验证网络、未验证、认证门户、系统阻断、离线。旧默认网络的迟到事件不能覆盖新网络状态；回调还校验服务会话。网络出现本身不再被当成连接成功。
- 关闭过滤时不再把全部域名序列化到 JNI；规则列表和版本来自同一份不可变快照。恢复观察成功后清除过期错误提示。
- 订阅下载开始时在同一锁内读取地址和配置版本，避免分开读取产生错配。保留原有过期提交检查、失败保留配置及回滚点。

## 回归发现并修复

首轮 Android 完整编译通过，但首页回归失败：日志测试返回首页时，旧的结构刷新标记没有被显式页面渲染消费，紧接着计数更新又重建了整个首页。现将该标记在首页完整渲染时清除，并把测试改为主动设置该标记，保留原“计数更新不重建页面”断言，使复现不依赖设备时序。不是删掉失败断言或把失败记为通过。

## 使用

代理页 → 总览或配置 → 应用放行。勾选的应用不使用本 VPN；更改后回到代理页，停止再连接。查看“当前生效设置”，不要把已保存数量当成本次已应用数量。

## 验证方式

`python3 tools/test_java.py --protocol-only` 检查协议与纯状态模型。新增状态机/名单检查 34 项、10,000 轮迟到切网事件组合。完整 Android 编译、界面与存储、独立 UID 实际 VPN 流量的结论以本次 CI 结果为准。

新端到端探针在模拟器启动实际 Mihomo VPN，使用另一个应用 UID，依次检查普通代理/广告拒绝、停止/重启、放行后的直接访问、运行中改名单但未重连仍保持旧路由、重连移除放行后重新经过 TUN。测试仅访问本地受控服务器，不使用私人订阅。新增浅/深色名单入口与配置快照检查。

## 边界

这次修复的是网络状态报告及应用分流接线，不是完整重写原生内核的断网重连。Android 的 VALIDATED 不能证明某个代理节点可达。模型测试不等于实体手机的 Wi-Fi/蜂窝切换、熄屏、重启或 OEM 策略验收；不承诺零泄漏或严格 kill-switch。

最近观察仍是间隔采样，不是完整 DNS/REJECT 日志。Root TPROXY/eBPF、HTTPS 内容过滤、全应用广告清除不在本次完成范围。

CI 使用临时证书做模拟器安装，输出给签名环节的是未签名 APK。正式交付必须使用现有测试证书，核对 SHA-256 `6e439a76bea55e2ebf2f5ee4c5892a04d7425e5f94b9c26c711b4747f195de06`；不得换签冒充可覆盖升级，不得把未签名包称为可安装版。源码 ZIP 不可刷入。
