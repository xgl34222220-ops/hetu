# V20.72 Google 服务断网与点击闪退修复候选

版本：`0.12.2-v20` / `2072`。基于成功运行 `37064619619` 的 V20.71 有效源码，测试分支 `test/v20.72-google-firewall-crash`。

## 已确认问题与修改

- V20.71 的 Java 启动请求发送 31 个字段（含操作名），打包 Root 脚本仍将开启厂商防火墙清理视为不支持的扩展控制。本次仅开放该开关的 0/1 协议，其他尚未实现的扩展仍明确报错。
- 开启设置 → Root 代理设置 → 其他配置 → 厂商防火墙“启动时清理”后，启动时检查，并在现有运行监护中每 60 秒检查。维护前后核对本次会话、实际核心 PID 和事务锁，代理停止或开关未开启时不清理。
- 从 Android 包管理器重新解析各用户/工作资料的 `com.google.android.gms`、`com.android.vending`、`com.google.android.gsf` UID。仅删除 `fw_INPUT`、`fw_OUTPUT`、`fw_OUTPUT_oplus_dns`、`zte_fw_gms` 中精确匹配这些 UID 的非反向 `DROP`/`REJECT` 规则，覆盖 IPv4/IPv6；不清空系统链，不修改 Doze/待机链、其他应用、UID 范围或带引号的规则。
- 系统重新插入相同拦截规则时下次检查可再次处理。操作失败记录计数，不以全局 flush 兜底。清理日志限制 60 行，现有消息与网络诊断包含状态和最近日志。
- 16 处文件选择器入口（配置、启动配置、备份、文件、核心、订阅、策略图标、脚本）捕获文件选择器不存在或权限被系统拒绝的异常并显示提示；无关程序异常继续交给系统，不能用全局吞异常掩盖错误。
- 新增一份本地、最多 16 KiB 的上次 Java/Kotlin 未捕获异常记录，包含版本、设备型号、页面、线程、异常类别及源码栈；不保存异常消息或用户配置，不自动上传。记录后继续调用 Android 原崩溃处理器。现有 工具 → 诊断与维护 → 消息与网络诊断 → 复制 可读取。
- 运行协议修订为 148，使后续启动使用新脚本；原 21 个核心/原生载荷保持既有哈希与签名身份。

## 使用与尚未确认

覆盖安装后开启“启动时清理”，停止再启动代理，使新运行会话启用维护。该功能依赖 Root；未包含真实手机上 ColorOS/HyperOS/ZTE 防火墙与长时间外网连接验证。Google 断网还可能由节点、DNS、QUIC 或系统后台限制导致，不能据此断言全部解决。

用户尚未提供具体闪退按钮和原始堆栈。本次修复已识别的文件选择器失败路径，并增加其余闪退的诊断证据；不宣称修好了所有点击崩溃、原生崩溃、进程被系统终止或 ANR。
