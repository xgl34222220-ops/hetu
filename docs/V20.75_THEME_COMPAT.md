# V20.75 自定义配色兼容修复

## 用户诊断与已确认问题

用户 PLK110 / Android36 的本地崩溃记录来自 0.12.2-v20 (2072)，在 ProxyScriptsActivity 的 HetuTheme 配色初始化触发 java.lang.NoSuchMethodError。不能把历史记录日期或版本说成当前 App 的新崩溃。

仍在当前 V20.74 APK（SHA-256 ea8569b8d3c1aea7ddd969eb9e1f8a6d721dd653ebf554147ae3bbaa6c5d303f）中确认同一 ABI 缺陷：material-kolor 2.0.0 的 toDynamicScheme 引用 SchemeTonalSpot(Hct,boolean,double) 等旧构造方法，APK 中 MCU 5.0.1 仅定义带 ColorSpec/Platform 参数的新构造方法。DEX 定义与引用精确比较发现 12 个 MaterialKolor 构造方法缺失，其中包括 9 个 Scheme 构造方法。自定义 accentHex，或者非默认 colorPalette 且未启用系统 Monet 时进入该路径；默认强调色/TonalSpot 与系统 Monet 分支绕过它，因此之前默认配色安装测试漏报。

MiuiX 0.9.4 的版本目录确认 materialKolor-utilities 5.0.1；此次将主题与 MCU 统一严格锁定 5.0.1，并适配 isDark 参数名，保留所有 8 个用户可选 palette、强调色、系统 Monet 与 SPEC_2021 默认算法。Material3、MiuiX、核心/native、Root 脚本、自启脚本、现有 UI 功能保持。关于页版本标识同步。Root runtime 继续 150。

用户当前诊断为 App 2074，但 proxyRootAppliedRuntimeRevision=149，service.d 脚本修改时间 19:56。upgrade-required/session-manifest-missing 来自尚未替换的旧运行会话，不以网站可达冒充完整性健康。覆盖安装后要显式执行首页橙色重启，部署已在 V20.74 修复的 Root150 并重建会话健康基线。不能隐藏警告、对不受信任现网直接补快照或自动强制重启。

Google 防火墙 checked=6/removed=0/failed=0，且 GMS/mtalk 已有双向流量；不足以证明此前间歇断网根因，也不能说清理了防火墙规则。
