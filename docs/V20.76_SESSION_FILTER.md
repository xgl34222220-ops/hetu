1. 当前 APK 的健康检查器独立部署在 /data/adb/hetu/run/state/hetu-health-checker.sh，不替换运行控制脚本、核心或开机入口。读检查使用独立锁，保留观察票据。旧状态返回的 healthy 必须由新检查器核对；检查失败不会回退成 healthy。
2. 工具→诊断工具→修复运行记录仅接受原 baseline checksum 完整、PID 一致，session 唯一差异为末尾合法 Google 清理行的已知缺陷。逐项核对保存规则、唯一挂接、策略/本地路由、TCP/UDP/DNS 监听、核心私有可执行身份、watchdog 命令与核心 PID。观察未知、其他差异、缺失快照、规则损坏等拒绝修复。
3. 修复只把已知 session 字段复制到原规则快照的事务副本，重算元数据 checksum。校验阶段比较核心开始 ticks，保留原 baseline 证据，发布失败回滚；不操作网络、不重启核心、不修改用户偏好或虚报已应用 runtime。强制 kill 在两个目录重命名间发生时会失败关闭，保留旧证据，需要后续显式处理；不掩盖中断。
4. 健康核验现在包括核心/守护身份；缺失守护、监听或读取错误不触发无条件规则重建。已确认且有可信 baseline 的规则/路由缺失仍用原有受限修复，不改其他所有者的规则。
5. 广告过滤从可清理的 cache 迁到 noBackup 稳定目录。每个 generation 发布完整不可变 block/allow/meta 对；索引和内容均核验 SHA-256。失败不改旧索引或交接文件；Root 启动复制先准备两份并校验再发布。旧导出代际暂保留，避免删除尚在交接的文件；未实现跨进程安全的长期代际回收。
