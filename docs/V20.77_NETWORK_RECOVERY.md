## 参考与采用理由

- [CMFA NetworkObserveModule](https://github.com/MetaCubeX/ClashMetaForAndroid/blob/94ebfd648abae76d32ae2191cfc413482d654c66/service/src/main/java/com/github/kr328/clash/service/clash/module/NetworkObserveModule.kt)：链路属性变化会触发 DNS 更新。河图 Root 服务原来没有消费 links 回调，因此相同网络上的 DNS/接口更新可能没有及时触发重新检查。
- [SFA DefaultNetworkListener](https://github.com/SagerNet/sing-box-for-android/blob/5c7b4ce969b926063737d059edf7b256c8f56ed0/app/src/main/java/io/nekohasekai/sfa/bg/DefaultNetworkListener.kt)：串行网络事件及当前网络校验可防旧事件干扰。河图已有 NetworkEpoch 和 ProxyNetworkState，直接复用；补充“网络编号重复但代次不同”的结果校验。
- [Android NetworkCallback](https://developer.android.com/reference/android/net/ConnectivityManager.NetworkCallback)：消费 capabilities、links、blocked 回调参数，避免在回调内同步回读 capabilities/links 所产生的竞态。沿用 registerDefaultNetworkCallback，未引入 requestNetwork 或新的网络控制权限。

## 本批改动

- Root 默认网络恢复消费 available、capabilities、links、blocked、lost；忽略旧网络迟到事件，同网络链接或关键能力变化也更新代次。
- available 不等于链路就绪：等待物理 INTERNET 网络及接口信息；blocked、认证门户、VPN 网络不触发此恢复。系统 VALIDATED 不是启动前提，避免透明代理启动与网络验证互相等待。
- A→B→A、DNS/接口变化、停止意图和控制事务都会使旧出口/健康观察失效。回写与事件状态变化共享锁；出口限频也绑定同一快照，避免旧任务覆盖新代次的限频重置。
- 变化后的旧 reachable 状态置为 unverified，保留核心和连接。2.5 秒合并恢复任务，只保留一个待执行计时任务；重复回调不重复排队。启动前在控制锁内再次检查代次。
- 有效网络变化沿用现有仅针对河图自有规则的原位检查/修复；不会自动执行 V20.76 的历史基线修复，不将当前未知规则重新认作健康基线。
- APK 2077 / 0.12.7-v20；Root 151、原核心、service.d、固定签名和现有 UI 方向保留。未更改 Manifest、节点、私人 DNS、系统防火墙或设备权限。
