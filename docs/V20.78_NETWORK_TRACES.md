## 实现

- 新增私有 `noBackupFilesDir/hetu-network-events` 分段 JSONL，追加而不覆盖已有记录。每条有 UUID、wall time、elapsed time、网络代次、阶段、结果、返回码；修复请求与结果、过期丢弃以 parent UUID 关联。
- 记录 network change、repair request/result、health result、egress request/每目标结果/最终结果 和 stale result。结构故障代码白名单包括 session-manifest-missing、监听、规则/路由读取与守护身份；无法归类的代码仅记 unclassified-fault。
- 异常只保存类型、最多四层 cause、每层三条调用位置；不保存消息、完整堆栈、URL、SSID、IP、配置或凭据。两个现有固定 204 目标使用 GOOGLE_204 / CLOUDFLARE_204 标识；备用成功不抹掉前一个失败，切网后不继续发起旧代次的第二个请求。数据面完整性与规则出口可达分别记录。
- 原位修复保留 shell 返回码，0 仅代表请求返回，不表示健康；随后独立检查原基线、规则、DNS 监听与守护。读取失败保存 unknown / health-read-failed / 新时间 / trace ID；不沿用旧 healthy 结论。
- 回调不写盘；队列满、目录/磁盘写失败只影响诊断，明确累计 dropped 计数，不改变 wanted 或代理健康。后续写入成功也不会清零缺口数量。
- 残缺尾行原样保留，后续完整记录另起一行；读取跳过残缺并报告 unreadableLines。分段按持久递增编号排列，避免墙钟回退破坏顺序。
- 诊断工具保留现有布局、报告抽屉与复制操作；独立入口不需 Root。完整消息与网络报告也包含事件与 trace ID。未新增开关、网络设置、权限或系统日志收集。
- APK 2078 / 0.12.8-v20，Root 151；原核心/21 个 native、service.d 与固定签名不变。

## 限制

本批不是通用抓包或所有错误的统一日志；开机/自动匹配/广告规则下载等既有详细报告仍独立。记录 ID 关联已接入的网络恢复与观察阶段。已有历史事件不会凭空补回；写入缺口会显示数量。

为遵守不永久删除数据的要求，旧分段不自动清理，长期占用会增长；视图读取有边界，不承诺归档空间永不不足。写失败仍保留应用可运行与错误计数，不扩大存储权限。

所有 Root 返回、网络事件与故障均为隔离夹具注入。Android AOSP UI 验证不等于 KernelSU 真机切网/自启或长期消息验收。用户手机间歇断网仍未确认，不能据 Google 204 可达或单次结构核验说已解决。已进入 Root shell 的启动事务不会被新代次强行中止；长期 IPv6/TUN/eBPF、Google/微信延迟仍待已有授权的相应实机环境。
