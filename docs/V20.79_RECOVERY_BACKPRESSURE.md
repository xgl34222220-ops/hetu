## 复现与选取理由

原创 `tools/qa/test_network_recovery_stress.py` 编译实际生产 `NetworkEpoch`、`ProxyTaskCoalescer`、`ProxyNetworkState` 及从服务逐字提取的排队方法；只替代该边界的 Android 依赖、时钟/工作线程派发和 Root/HTTP 执行。不是另写一个恢复器。旧服务 SHA256 `b50773343de46622658e65b48a3e00a96863d74033f561fd6bdab304402ae1cd`。

在工作线程被占用时，让512次 available/capabilities/DNS/blocked/unblocked 及计时器完成：旧服务排入512项恢复，511项最终过期，虽没有重复 Root 恢复，等待队列仍无界；4096项真实 ScheduledThreadPoolExecutor 取消任务会继续保留到到期。本地改后，待执行恢复最多1项，最终只检查最新代次，取消计时器保留0项；执行中到达的新代次仍保留一次后续检查。完整前后夹具在 CI 重新执行并输出 `network-recovery-stress.json`，不拿本地结果替代 Android 门禁。

服务重建时，旧 persisted healthy/reachable 与全新 waiting epoch 原先短暂并存；旧服务 core probe 使用全局控制票据，却未核对观察实例。本批先让当前观察 unknown/unverified、时间归零、生成新 session UUID，再接受新回调/独立健康结果；保留 wanted/core flag 和原日志。旧实例的健康、出口及 core probe 回写均经过实例和原控制票据门禁。原网络代次机制继续复用，旧/新实例同数字 epoch 由 session 区分。

## 参考源码、文档与许可证

- [SFA DefaultNetworkListener.kt](https://github.com/SagerNet/sing-box-for-android/blob/5c7b4ce969b926063737d059edf7b256c8f56ed0/app/src/main/java/io/nekohasekai/sfa/bg/DefaultNetworkListener.kt)：串行事件及当前网络筛选有助于减少旧事件干扰。河图保留现有 reducer/coalescer，只给恢复队列接入同一合并器，不移植阻塞 callback、requestNetwork 或新权限。
- [Android ScheduledThreadPoolExecutor](https://developer.android.com/reference/java/util/concurrent/ScheduledThreadPoolExecutor)：采用 remove-on-cancel 与关闭后不继续延迟任务的自有计时器策略，解决已复现的取消任务滞留。
- [Android NetworkCallback](https://developer.android.com/reference/android/net/ConnectivityManager.NetworkCallback)：继续消费回调参数，blocked 只代表调用河图 UID，不能据此证明 Google/全设备被禁网。
