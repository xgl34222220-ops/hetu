## 本轮缺口与实施

1. 运行状态：成功 Root 观察的 `running=false` 会被旧 fastRunning 缓存反转为 true。以本轮明确观察为准；未知/观察失败保留可用状态并显示不确定，避免误报已停止或无依据的正常运行。
2. 请求归属：原 global 和非 Selector 批次已有身份校验；Selector 整波 groupDelay 缺少同类校验。同 PID 下还需核物理网络代次，防止切网前请求写回。节点选择事务原本会在 PUT 后重新读取当前 API，跨 API 时可能把旧连接 ID 用于新控制器；选择事务固定目标并核自身 owner。成功路由策略 mutation 使旧网站测速失效，失败 mutation 保留可用结果。
3. 规则与规则集：追加读取、更新、取消、重复操作和旧批次完成后的结果归属。API/core/config 内容身份变化触发重新读取，物理切网保留已知内容；批量更新只以当前 API 返回的清单为目标。全量回读接管旧任务时正确释放加载状态；单项确认回读允许补入缺失实体。缓存健康观察保留最后确认的核心 PID，避免下次真实 PID 变化漏检。
4. DNS 诊断：NXDOMAIN、只有 IPv6、解析失败、非 fake-IP 回答不能唯一证明系统 DNS 绕过核心。只把有效 fake-IP 阳性作为进入核心的证据，其余显示无法判断，避免误定因。
5. 视觉：复用当前四 Tab 布局与共享组件，通过静态径向色团、透光渐变表面和细边框统一主页面、子页、菜单、弹窗、sheet、空/错误/加载状态。保留纯黑偏好、系统字体、现有颜色算法和减少动画设置；不引入每张卡片实时模糊或永动动画。
6. 首页连接观察：核心运行、控制接口可读、网络接管完整与规则出口探测分别解释。局部控制/接管成功不等于 Google 认证成功或全互联网在线。
7. 守护恢复：原前台恢复只开启 UI 轮询，核心仍活但 Android 守护服务已结束时不会重新附着。前台恢复入口仅按用户当前启动或网络自动化意图确保已有守护服务，不替换可用核心、配置或权限。停止意图与服务自身的恢复闸门继续生效；OEM 杀后台仍需真机确认。
8. 恢复冷却：原守护服务用持久化系统时间计算 30 秒间隔，校时回拨会阻塞已确认退出的核心恢复。间隔改用当前服务实例的单调时钟，系统时间只作诊断记录；新服务实例仍须经过真实进程、当前网络、用户意图及控制锁核查。

## 参考与采用理由

- [Android 默认网络状态与回调](https://developer.android.com/develop/connectivity/network-ops/reading-network-state)：使用 capabilities/link 回调的新观察，旧网络 onLost 不覆盖新网络；可用与已验证分开。
- [NetworkCallback API](https://developer.android.com/reference/android/net/ConnectivityManager.NetworkCallback)：按回调来源和当前网络身份核结果归属，不以一次 onAvailable 宣称可联网。
- [InetAddress API](https://developer.android.com/reference/java/net/InetAddress)：UnknownHost/解析错误仅说明没有确定地址，不能证明某一 DNS 接管根因。
- 复用仓库已有 Mihomo 载荷与许可证，未升级原 native/core，未复制第三方 UI 或引入额外依赖。
