# test.134 · 实机反馈修复

本次依据用户的三张 test.133 截图和明确反馈，范围包含界面与运行时修复。此前仅允许 UI 变更的运行时哈希基线不能替代功能验证；本次仅对经过审查的修复文件更新基线，并保留行为、配置与隔离网络测试。

## 已定位的问题

- 原生策略面板只读取 `/proxies`，遗漏订阅 provider 的节点和测速历史；对 provider 节点调用普通节点测速接口，错误又被统一标记成超时。刷新使用 `putIfAbsent` 会保留旧的失败值。
- 河图广告规则可能放到普通分流规则之后，被前面的 GEOIP、GEOSITE 或普通 RULE-SET 提前放行。
- 本地、远程与 Sub-Store WebView 直接作为 Activity 内容，未在 Android 强制 edge-to-edge 下处理系统安全区域。
- 工具、设置共用行只有 14sp 标题、11sp 说明和 56dp 最小高度；过厚底栏、较高页头、滚动节点名降低了可读性。

## 修复

订阅测速使用 provider 专用 healthcheck，合并 HTTP/File provider 的节点和按 URL 保存的历史。嵌套策略读取所选叶节点，旧刷新请求不能覆盖后来完成的测速；API 鉴权/路径错误、真实超时、失败和未测分别处理。IPv6 能力探测不再污染普通延迟。

广告链在普通分流之前执行，明确白名单及安全规则保持优先。开关执行热重载并读取实际 Controller 规则、provider、运行模式确认。未生效或未确认时如实显示，规则未变化也可重试此前失败的热应用。详见 `adblock-test134.md`。

TPROXY 用独立 connmark 位识别本会话接管的 TCP 流，避免把代理启动之前的旧连接送入全新监听器。运行环境修订号单独跟踪，应用更新不会自动重启代理，也不会误清待应用修复。详见 `test134-message-continuity.md`。

三个 WebView 入口共用原生安全区域容器，处理状态栏、挖孔、导航栏与键盘，并保留页面历史。工具与设置改为 18/14sp、80dp 最小行高；策略采用独立当前节点行、静态省略、真实可用数与分色延迟。底栏改为单层磨砂、平面滑动选中态及按压弹性反馈。大字体标签宽度随字体缩放。

## 验证项目

- 16 项测速 Controller/历史回归，包括 40/81 节点复现、编码路径、HTTP/File provider、错误分类和刷新顺序。
- 4 项 WebView 容器安全区域及入口回归；3 项升级广播和运行环境待应用回归。
- 正常与 1.5 倍字体的四个完整生产页面渲染，列表字号和底栏留白断言，以及实际按压/展开动画帧。
- 既有页面、配置编辑、策略选择、长名称、深浅主题及大字号回归。
- 广告生成、真实 Mihomo 匹配与 wire-format 合约；隔离 Linux 网络包、既有 TCP 连接与双栈、应用范围和 DNS 回归。

`tests/ui-runtime-baseline.json` 本次仅更新已审查的 Root 脚本、启动/重载管理器、配置生成器、控制 API、数据仓库、升级接收器及真实引擎广告测试。基线继续拒绝其他未审查运行文件变化。

## 交付边界

测试包沿用固定 preview 包名与证书。界面预览由实际生产组件渲染，使用示例数据；模拟器软件渲染不代表用户手机的 GPU 帧率。网络回归验证具体连接与规则行为，不据此声称已在用户手机上复现所有微信消息延迟。

本次修复涉及已运行的 Root 网络脚本。APK 安装不会强制打断当前代理；需要明确的用户操作应用新的运行时，界面必须清楚提示待应用状态。
