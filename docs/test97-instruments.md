# test.97: instruments and ticket cards

This iteration preserves the existing two-column strategy grid, in-place expansion, callbacks and runtime configuration. It addresses the remaining call sites rather than promising that changing a color token alone fixes every page.

- Home data is four individually lit cards separated by physical gutters, not a white surface with cross dividers. Current up/down byte rates are shown in the hero; no generated waves or invented signal quality are used.
- Both provider and subscription-library screens use the same ticket component. Usage is shown as used / total, with a real blue/cyan progress track, node count when reported, expiry date and local-day update time. Unknown values stay unknown; upload/download details remain accessible.
- Rule batching was already 15 in test.96. It is retained exactly, including original order and duplicates; the group now actually uses the shared crystal material and expanded composite expressions are not cut at five lines.
- The material adds an inset light rim and stronger restrained blue/teal ambient reflection; popover background is not prefilled with an opaque page-color slab. Foreground labels remain sharp. Existing blur-off and dark-theme paths remain supported.
- Original configured icon URLs, cache, color and aspect ratio are retained. Visible cards retry a failed load with bounded delays and on foreground/runtime-port changes, instead of staying stuck on their initial failure. No substitute brand image or generic Tune logo is presented as the configured image.
- No Root/network-control file is changed; the existing runtime-boundary hash checks are required. All new gauges use reported data.

Automated rendering checks layout and data semantics, not OEM GPU backdrop rendering or real remote-image reachability. A passing build is not a claim of real-device visual approval.
